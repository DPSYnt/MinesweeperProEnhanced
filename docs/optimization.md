# 2026-10-30 代码优化记录

本文按版本保留历史记录，历史章节中的“当前”指对应版本。现行实现已取消安全格排雷惩罚、开局强制有解和持续修盘，鼠标输入优化见下方“取消排雷惩罚与有解保障，优化鼠标输入”一节。

本次针对重复读取、排雷数字计算、探索临时数组、鼠标坐标轴更新和控制器动画回调进行优化。难度、雷数、随机数调用顺序与游戏规则保持一致。

## 具体变化

| 位置 | 原行为 | 当前行为 |
| --- | --- | --- |
| `GameEngine.snapshot()` | 每次创建全部格子和位置，并多次扫描计数 | 状态与秒数未变时复用不可变快照；状态变化后一次扫描生成数据；仅秒数变化时共享不可变棋盘 |
| 界面计时 | 每秒取整盘快照，再读取用时 | 直接调用 `elapsedSeconds()` |
| 单颗右键清雷 | 全盘重算邻雷数字 | 只更新目标和八邻格；排除核心时额外恢复对应区的真实数字 |
| 安全格探索 | 每次分配棋盘面积大小的队列 | 同一局内顺序复用队列，重开按新尺寸分配 |
| 坐标轴悬停 | 每次扫描全部行列并创建字体 | 复用字体，只更新上一位置和当前位置；同尺寸重开清除旧高亮 |
| 控制器完成回调 | 重复回调仍可能重复渲染和展示结果 | 每次操作有独立版本，完成只交付一次；渲染期间重开会取消旧结果 |
| 被拒绝的操作 | 重新渲染棋盘及打开的记录窗口 | 仅显示动作提示 |

### 修复保障布局的重复排雷问题

复现原因是局部构造没有排除 `flagged` 的已清除格：玩家扫除保障移出的普通雷后，该格已揭开且标记为已清除，但下一次修复仍可将它收起，并从其他未知位置移入另一颗普通雷。实际总雷数下降，玩家却在同一位置连续排雷，看起来像同一颗雷未清掉。四档各 30 个固定种子的残局操作轨迹均可复现，旧版共 120 局失败。
