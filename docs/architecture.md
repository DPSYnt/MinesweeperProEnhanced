# MinesweeperEX 架构与规则实现

## 分层与数据流

调用方向为 `MinesweeperApplication → ui → controller → service → model/config`。控制器通过 `GameView` 回调界面；服务层不引用 AWT 或 Swing，可独立运行。

| 层 | 关键类 | 职责 |
| --- | --- | --- |
| 启动 | `MinesweeperApplication` | 在 Swing EDT 创建窗口 |
| 配置 | `GameRules`、`Difficulty` | 游戏名、难度尺寸、比例雷数、区域大小、HP、伤害与增长率 |
| 模型 | `Cell`、`Position`、`InformerZone`、`GameSnapshot` | 不可变状态、格子类型、动态区域尺寸与统计 |
| 游戏服务 | `GameEngine` | 动态初始化、合法性、探索、排雷、爆炸、环境变化、胜负 |
| 成就服务 | `AchievementService` | 本次运行期间的累计进度与成就 |
| 控制器 | `GameController`、`GameView` | 串行动作、动画期间输入保护、重开与旧回调失效 |
| 页面 | `MinesweeperFrame`、`StartMenuPanel`、`GamePanel` | 菜单 / 对局切换、难度选择、继续当前对局、窗口生命周期 |
| 棋盘 | `BoardPanel`、`BoardViewport` | 动态格子、鼠标手势、坐标轴、滚动与缩放 |
| 辅助视图 | `RuleBook`、`RulesPanel`、`RuleDiagram`、`RecordsPanel`、`GameDialogs` | 规则图文、集中记录及辅助窗口复用 |
| 主题 | `UiTheme`、`IconFactory` | 字体、配色、圆角卡片、按钮和缓存图标 |

不依赖数据库、网络或持久化层。`GameEngine` 独占可变棋盘，其他层读取不可变 `GameSnapshot`。每格只有一个 `MineType`，避免雷种重叠；行列使用 `Position`，不借用图形类。

快照按实际状态变化缓存：成功动作和重开使旧缓存失效，下一次读取用一次棋盘扫描同时生成格子、普通雷数、揭开数及各区余雷数。没有动作且秒数相同时直接复用不可变快照；只有用时变化时共享不可变格子和区域列表，更新统计对象。保存的旧快照不会随引擎改变。界面计时器通过 `elapsedSeconds()` 直接读取用时，不创建棋盘快照，终局仍冻结时间。

## 难度与动态棋盘

`Difficulty` 是菜单、引擎、规则表、统计共用的唯一难度数据来源。普通、困难、地狱、噩梦的棋盘依次为 18×18 / 25×25 / 30×30 / 35×35，全部普通雷初始数量为 67 / 157 / 267 / 397；每局另有两颗内鬼雷（即每区唯一核心）和一颗国王雷，初始总雷数为 70 / 160 / 270 / 400，初始 HP 为 5 / 4 / 3 / 2。区外普通雷增殖率为 12% / 15% / 18% / 20%，每颗引爆地雷分别扣 1 / 2 / 3 / 4 HP。排雷操作命中安全格时无响应。

初始总雷数在难度配置中明确指定，确保实际放雷与所需整数总数一致；具体值见 [游戏规则](rules.md)。每区雷数仍从旧 20×20 参数按面积换算，额外乘以 `GameRules.MINE_DENSITY_FACTOR`（0.85）后四舍五入得到。`initialMines()` 从初始总数扣除两颗核心和一颗国王，统计区内、区外全部普通雷；`initialOutsideMines()` 从初始总数扣除两个区域的全部雷和一颗国王，仅用于初始化区外普通雷。`zoneMineCount()` 表示每区初始总雷数，其中一颗为内鬼雷。`GameSnapshot.remainingMineCount()` 扫描真实雷类型，侧栏不把普通雷计数冒充总数。

每次重开按所选尺寸重新分配棋盘和邻接表。内鬼区尺寸为 4×4 / 6×6 / 8×8 / 10×10，每区雷数为 7 / 13 / 19 / 26。先在区域内部随机选定唯一的 `INFORMER_CORE`，行列偏移均在 1 至 `size - 2`，避开最外层一圈；再对全区其余格洗牌放置 `NORMAL`。整个区域始终保留 `informerId` 归属，区内普通雷不参与环境变化时的增殖与重排。初始化枚举合法区域起点并洗牌，找到首对互不接邻的区域即返回，避免构造所有区域组合。放雷使用有限候选列表与洗牌，数量超过容量时截断为实际可放数量。

开局展开左上 5×5 安全区，其余地雷按合法位置随机分布。开局强制数字推理及持续有解修复均已移除，动作交付前不再扫描约束或改变布局；普通安全探索及排雷只按原规则更新揭开状态和邻近数字。

## 规则边界

公开动作是 `reveal`、`flag`、`chord`、`endTurn`、`restart`。普通探索与排雷先检查游戏状态、边界、是否未知及与控制区的八邻接关系，非法操作不改变统计。右下国王区也遵守相同可操作范围。

`chord` 验证起点是已揭开、无内鬼干扰且当前显示数字为零的格子，并要求有未知邻格。本作右键清雷会降低当前数字，因此归零等价于经典扫雷已标出全部周围地雷。使用邻接表批量展开，只计一次操作，不逐格回调控制器。数字尚未归零、干扰或无目标均拒绝，不读取隐藏雷位置来判断可否辅助。单纯探索或辅助展开不清除地雷，也不再因安全格全部揭开而触发胜利。

合法动作同步完成全部结算，返回含爆炸坐标和新增成就的 `ActionResult`。动画只展示结果，不再扣血或修改雷数。引擎由调用方串行使用；生产界面在 EDT 上调用，测试注入 `Random` 和 `Clock` 以复现结果。

右键排雷时先记录目标是否为国王，完成单颗清除、HP 奖励与统计后，若排除了国王立即失败，不进入环境变化。左键踩中国王或被附近爆炸波及时，先完成局部爆炸伤害、计数和数字更新，再以国王被引爆判定失败；此原因优先于同次 HP 耗尽，后续不再收缩、移动国王或增殖。清除国王时将 `kingIndex` 设为 `-1`，快照的 `kingPosition` 为 `null`。存活国王只在右下 5×5 的未知空格中选位，旧位置也是候选，因此可以停留。

唯一胜利条件为场上只剩一颗存活国王雷，不要求揭开全部安全格。`checkOnlyKingRemains` 在非国王排雷成功后检查；爆炸则先判定国王损失和 HP 耗尽，再检查胜利，获胜后不进入环境变化，避免最后一颗雷清除后又增殖。内鬼雷引爆后先再生，因此仍阻止胜利；正确排除最后一颗核心可立即获胜。环境变化结束时也检查余雷。HP 耗尽立即失败，控制区少于 20 格只在环境变化后检查。结束后冻结计时。胜利解锁“国王守护者”与其他胜利成就，清除国王不授予胜利成就。成就与累计清雷数跨本次程序内重开保留，其余单局状态重置。

## 爆炸与内鬼结算

任何雷种被踩中时，都只收集起点及其八邻格内的普通雷和国王雷；邻格内鬼雷不受波及，只有直接踩中的内鬼雷参与本次爆炸。不递归扩散，也不将整个内鬼区加入爆炸。

集合去重后统一清除、计数并按难度每颗扣血，避免重复计数和动画重复结算。直接命中内鬼雷时，先记录区域归属，结算后调用 `respawnInformer` 在本区内部的未知无雷格重新生成唯一核心，避开最外层一圈，并更新 `coreIndex`；区域 `active` 保持为 `true`，不解锁情报。内部候选优先排除原格，无其他内部候选时回退仍未揭开的原格，避免无效循环或生成到已揭开格。即使本次伤害导致失败，也先完成再生和数字更新。爆炸不调用 `deactivateInformer`。

右键清除地雷时只处理目标一格，清雷数加 1，HP 恢复 1 并限制在 `GameRules.MAX_HP`（100）。满血时仍正常清雷、计数和更新数字，历史准确记录 HP 增量为 0；受伤后继续正常恢复。区内普通雷与区外普通雷一样揭开目标格；只有内鬼雷保持未揭开，以 `flagged` 标记已扫除，不增加控制区，再次排雷返回拒绝结果，可正常探索。正确排除内鬼雷立即将该区 `active` 置为 `false` 并解锁对应坐标情报，记录 `capturedTurn`，此后不再生；清除区内普通雷不会解除干扰。解除后保留所有格子的区域归属、其他地雷类型、位置与揭示状态，不自动揭开区域，也不会在后续普通雷重排时改变区内余雷。只有同回合解除两个区域的干扰才解锁相应成就。

`AchievementService` 提供 16 项会话成就，具体条件见 [成就说明](achievements.md)。动作结果生成前根据本局正确排雷、HP 和控制格数检查进度，累计清雷在实际清除时更新；难度通关和无伤通关只在获胜时检查。无伤条件使用“总清雷数等于正确排雷数”判定，与回合数无关。对安全格执行排雷不记错误或行动，也不影响成就；`GameStatistics.wrongFlags` 作为兼容字段固定为零，界面移除已无意义的标错次数和正确率。解锁集合按会话保存，重开不清空；界面统一读取枚举数量。

真实邻雷数与显示数字分开保存。干扰有效的区域安全格在真实邻雷数上随机加 1 或减 1，并截断到 0～8。开局、地雷首次变为安全格时初始化偏移，环境变化时重新采样；同回合更新邻雷数保留现有偏移，正确排除核心后恢复真实值，核心引爆再生则保留干扰。自动展开只使用真实零值且无干扰的格子，干扰零值明确显示而不触发展开。数字计算、辅助展开与棋盘紫色干扰提示都检查 `zone.active`，区域归属本身不再表示干扰仍然有效。快照按保留的归属统计区内剩余雷数，记录与侧栏在解除干扰后继续显示余雷。

右键成功清除单颗雷时，只递减八邻格的真实邻雷数，并用共用方法更新这些格子及目标格的显示数字，不重新采样干扰。核心清除时额外更新该区的显示数字。初始化、爆炸和环境变化继续使用完整重算，保留批量布局的明确结算边界。

## 环境变化顺序

1. 根据同一份揭开状态收集全部边缘，再统一收起一层，清除变为未知格上的旧标记。
2. 存活国王在未知空格内随机移动，保证不与其他雷重叠、不进入已揭开格。
3. 按现存区外普通雷数计算向下取整的增长量，仅在区外合法未知格重新布局，并按可放容量截断；区内普通雷保持原位。
4. 重算真实邻雷数与活跃内鬼区干扰数字。
5. 检查控制区是否至少 20 格，否则失败；通过后增加回合数，进入行动阶段。

零格扩展使用定长整数队列，在入队时标记揭开，每格最多入队一次。队列在重开时按棋盘面积分配，之后的探索与辅助展开顺序复用，避免每次点击分配整盘队列。邻接表随棋盘尺寸构建；边缘收集与完整数字计算均为棋盘大小的线性扫描。图标与爆炸帧缓存复用。

## 开始菜单和展示生命周期

`RuleGuide` 提供双端共用的简明书面规则、难度摘要与区域内随机布雷说明。桌面 `RuleBook` 渲染 HTML，Android 规则窗口渲染纯文本，各自补充鼠标或触屏操作；难度数值读取同一配置。当前源码取消安全格排雷惩罚和全部有解保障，两端也移除修盘提示；现有 Android 1.1 APK 尚未重新打包后续更新，Windows EXE 仍为历史 1.0.4。

`MinesweeperFrame` 使用 `CardLayout` 管理菜单与对局页面。选择难度只更新选择，点击开始才 `restart`。菜单根据无对局、进行中、已结束三种状态显示开始 / 继续动作和记录入口；继续对局不会使用当前选择的新游戏难度重开。返回菜单取消待完成的展示与手势；继续对局重新渲染当前快照。菜单不暂停引擎的经过时间统计，界面刷新计时器仅在对局页运行。

去掉窗口菜单栏及重复的教程、关于和独立地图对话框。对局页面集中提供记录、规则与返回菜单，结束回合和独立重开按钮在侧栏固定显示。重开通过专用回调复用控制器 `restart`，进行中先确认；结算动画期间仍可重开，控制器使旧动画回调失效。终局只禁用结束回合，胜利和失败弹窗均提供重开与重新选择难度。`RecordsPanel` 在三个标签页内展示统计、行动记录与会话成就，使用不可变快照和只读历史，不修改引擎。行动后更新打开的记录窗口；手动刷新重新读取最新数据并保留当前标签。新游戏替换旧局记录。

`GameDialogs` 由主窗口持有，规则与记录各保留一个实例，重复打开激活已有窗口，关闭后允许重建。结束时当前 `GamePanel` 已按终局模式展示全图，结果摘要直接导航到记录、菜单或当前棋盘，不再复制地图窗口。

控制器为每次操作分配递增版本号，使重开、取消展示及后续操作之前的动画回调失效。每个完成回调只交付一次，重复调用不会再次渲染或显示终局，也不能解除后续动画的输入保护。渲染期间若发生重开，旧结果不会继续展示；拒绝的操作返回结果，不刷新棋盘和记录窗口。输入保护覆盖整个动画周期，游戏规则始终先于动画完成。关闭窗口停止所有 Timer 并关闭所属规则对话框。

棋盘按快照尺寸创建 JButton 网格并保留键盘可访问性。全部格子共用一个 `MouseAdapter` 和一个焦点监听器；鼠标使用按下 / 松开手势，以起点、按钮和真实棋盘版本校验。同格轻微拖动有效；已揭开格上的左右键组合或左键双击进入辅助模式，预览相邻未知格，第一键松开时只调度一次 `chord`。右键不使用系统多击计数过滤，每次独立按压都可派发；只有左键的偶数次点击进入双击处理，未知格的第二次左击仍受保护。检测到同一按钮再次按下且另一按钮未按住时，清除遗留状态并开始新手势，避免丢失松开事件后吞掉下一次点击。跨格组合、跨格松开、窗口失焦与动画锁定仍取消手势。合法操作提示只依赖公开揭开状态，不读取隐藏雷种。

棋盘渲染按不可变 `cells` 列表识别实际版本：相同列表和展示模式直接复用，计时快照共享同一列表，不取消正在进行的按压，也不重建 1,225 个格子的无障碍文本。真实换盘时才失效旧手势。每次新盘面只为实际变化的格子更新描述和绘制，仅在启用状态、光标或动画图标变化时写入相应属性；重复启用输入不取消手势，同格拖动中保持相同按压反馈时不重复清空和重绘预览。

`BoardViewport` 用整数像素保持方格及坐标轴对齐，自动格子范围 18–32 像素，手动缩放范围 18–42 像素；超过视口时提供双向滚动。方向键定位时将焦点格滚动到可见范围。侧栏只滚动局势与情报，回合操作固定显示；小窗口压缩留白并调整菜单卡片高度。`InfoPanel` 的固定操作卡片以 28 号字体显示本局计时，`GamePanel.updateTime` 直接更新该标签；控制区以真实格数、百分比和 10 像素高进度条显示，填充比例等于控制格数除以棋盘总格数。

坐标轴复用常规和高亮字体，悬停时只更新上一格与当前格对应的行列标签，避免每次移入、移出都遍历所有坐标并创建字体。同尺寸重新开始也会清除上一局高亮。已删除浮动悬停提示、悬停坐标文字及底部实时状态栏；操作说明保留在规则页和无障碍描述，行动历史及成就集中在记录窗口。内部 `Position` 与格子索引继续从 0 开始；棋盘刻度、无障碍说明、国王情报和行动记录在展示时加 1。Android 棋盘上方及左侧保留 24dp 刻度区，格子绘制和触控均限制在内容区，平移缩放保持刻度与格子中心对齐。

## 构建与测试

Maven 标准目录、Java 21，生成 `MinesweeperEX.jar`。本地 `build.cmd -Test -Preview` 只使用 JDK，严格编译并运行显式断言，不依赖 `-ea`。Maven 的 `test` 阶段也执行同一套 `RegressionSuite`。

测试通过公开动作构造局面，不通过反射修改引擎。覆盖四档共 800 个固定种子的随机开局、安全格排雷完整无响应、四档各 12 条普通动作轨迹不移动其他雷或收起已揭开格、HP 上限与爆炸受伤后恢复、新成就和跨局累计、内鬼核心内部生成及再生、国王损失立即失败、唯一胜利条件、爆炸结算、控制区同时收缩、增长容量、时间冻结与控制器回调。`UiInteractionChecks` 在无窗口 EDT 中派发真实 Swing 事件，覆盖快速连续右键、丢失松开后的左右键恢复、同盘和时间快照保留手势、真实换盘与动画取消手势、双键顺序与辅助预览、键盘操作、固定计时与进度条、四档菜单、缩放滚动及多尺寸布局。

优化回归额外检查快照缓存失效、仅用时变化时的不可变共享、重复完成回调、渲染中重开以及坐标高亮重置。`EnginePerformanceProbe` 使用固定时钟，对四档难度各 30 个种子、共 120 条轨迹、每条至多 120 次合法动作生成 SHA-256，包含每步完整快照、动作结果和历史；回归测试与当前规则保存的基线比较。它也可独立运行重复快照读取计时，不把机器耗时作为测试通过条件。原优化前后的比较、测量方法及新规则的基线更新见 [优化记录](optimization.md)。
